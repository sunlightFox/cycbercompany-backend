# Spring Agent Studio 前端界面规范

版本：1.0  
状态：强制执行  
适用范围：Spring Agent Studio 的 Web 前端、交互原型、组件和视觉资源

## 1. 规范等级

本文使用以下约束等级：

- **MUST**：必须满足，否则不得合并或交付。
- **SHOULD**：原则上满足；偏离时必须记录原因。
- **MUST NOT**：明确禁止。

本文是前端产品体验和视觉实现的单一真源。设计稿、组件库、页面实现与临时需求发生冲突时，以本文为准。任何违反 MUST 或 MUST NOT 的改动，必须先修改本文并获得确认。

## 2. 产品定位

Spring Agent Studio 是面向个人和团队的数字员工工作台，不是传统客服聊天窗口，也不是以配置表格为中心的管理后台。

前端 MUST 遵循以下优先级：

1. 对话问答和任务结果。
2. 任务执行状态和必要步骤。
3. 引用来源与知识依据。
4. 数字员工、Skill、MCP、知识库、模型和节点管理。

默认页面 MUST 让用户在 3 秒内理解：

- 当前正在和哪个数字员工对话。
- 当前任务是否正在执行。
- 用户可以在哪里继续输入。

## 3. 核心体验原则

### 3.1 对话优先

- 工作台 MUST 以消息流作为唯一主要内容区。
- 回答、执行步骤、错误和引用 MUST 属于同一条助手消息上下文。
- 页面 MUST NOT 设置常驻执行详情侧栏。
- 页面 MUST NOT 在工作台首屏展示统计卡片、欢迎横幅或功能介绍。
- 页面 MUST NOT 把 Skill、MCP、知识库或模型配置长期铺在工作台上。

### 3.2 渐进披露

界面信息分为三个层级：

- **一级，始终可见**：会话标题、数字员工、消息流、输入框、发送或停止。
- **二级，按需出现**：执行步骤、引用、消息操作、临时能力选择。
- **三级，管理入口**：Skill、MCP、知识库、模型、节点、日志和高级设置。

三级信息 MUST 通过弹窗、抽屉、菜单或独立管理页出现。三级信息 MUST NOT 抢占默认对话空间。

### 3.3 安静和克制

- 每个始终可见的控件 MUST 有明确的高频用途。
- 可以通过菜单访问的低频操作 MUST NOT 同时占据工具栏。
- 纯装饰元素 MUST NOT 添加。
- 界面 MUST NOT 使用营销式文案、功能说明段落或虚构数据。

## 4. 工作台结构

桌面端工作台由以下区域组成：

1. 收缩导航栏。
2. 顶部会话栏。
3. 居中的消息流。
4. 底部输入区。
5. 按需出现的弹窗、菜单和引用抽屉。

### 4.1 收缩导航栏

- 默认宽度 MUST 为 `56px`。
- 展开宽度 SHOULD 为 `224px` 至 `248px`。
- 默认仅显示：新建任务、搜索、会话历史、管理、设置。
- 展开状态可显示最近会话，但 MUST NOT 展示复杂树形导航。
- 移动端 MUST 隐藏导航栏，并通过菜单按钮打开抽屉。

### 4.2 顶部会话栏

顶部会话栏始终可见的内容不得超过：

- 会话标题。
- 数字员工选择器。
- 管理按钮。
- 更多菜单。

语言、主题、导出、删除和完整日志 MUST 放入更多菜单或设置弹窗。

### 4.3 消息流

- 桌面端内容最大宽度 MUST 为 `960px`。
- 推荐阅读宽度 SHOULD 为 `860px` 至 `920px`。
- 消息流 MUST 在可用空间内水平居中。
- 页面区域 MUST 使用自然分隔，不得将整个消息区包成装饰卡片。
- 用户消息与助手回答之间 MUST 保持明显但克制的垂直节奏。

### 4.4 输入区

输入区 MUST 包含：

- 多行文本输入。
- 附件或补充内容入口。
- 临时能力选择入口。
- 发送按钮；运行期间替换为停止按钮。

输入区 MUST NOT 默认显示：

- 模型参数。
- Skill 完整列表。
- MCP 完整列表。
- 知识库详情。
- 温度、Token 上限等高级模型设置。

临时选中的能力 SHOULD 以可移除的紧凑标签显示在输入框上方。

## 5. 消息规范

### 5.1 用户消息

- MUST 使用右对齐的中性浅灰气泡。
- 最大宽度 MUST NOT 超过消息区的 `78%`。
- MUST 支持长文本、换行、代码和附件。
- MUST NOT 使用品牌色填充整块消息。

### 5.2 助手消息

- MUST 使用无气泡的自然文档排版。
- MUST 按“执行过程、最终回答、引用”的顺序组织。
- 最终回答 MUST 是视觉重点。
- MUST 支持 Markdown、代码块、列表、表格和链接。
- 文本操作 MUST NOT 挤压或覆盖正文。

### 5.3 消息操作

复制、重试、反馈和更多操作：

- 桌面端 SHOULD 在悬停或键盘聚焦时出现。
- 触摸设备 MUST 能通过点击消息显示。
- 核心操作 MUST NOT 只能依赖悬停。
- 删除、导出和查看完整日志 MUST 放入更多菜单。

## 6. 执行过程规范

执行过程 MUST 嵌入助手消息，MUST NOT 作为常驻独立面板存在。

### 6.1 显示状态

- **执行中**：当前步骤展开，已完成步骤折叠为单行。
- **执行成功**：整体折叠为“已完成 N 个步骤 · 用时 X 秒”。
- **执行失败**：失败步骤自动展开并显示可理解的错误摘要。
- **等待用户**：明确显示需要确认或补充的信息。

### 6.2 单个步骤

单个步骤默认只显示：

- 状态图标。
- 动作名称。
- 可选的对象名称。
- 耗时或当前状态。

工具参数、原始 JSON、请求地址和完整返回值 MUST 默认隐藏。用户点击步骤后才可查看摘要；完整原始数据放入运行日志。

### 6.3 视觉形式

- MUST 使用细线、缩进和小型状态图标表达顺序。
- MUST NOT 为每个步骤创建独立大卡片。
- MUST NOT 使用持续闪烁、呼吸光或大面积进度动画。
- 当前步骤可使用轻微淡入或低对比度加载提示。

## 7. 引用与知识依据

- 知识库检索依据 MUST 默认隐藏。
- 最终回答中的引用 MUST 使用紧凑编号，如 `[1]`、`[2]`。
- 引用 MUST 可通过鼠标、键盘和触摸激活。
- 点击引用后，桌面端 MUST 打开右侧临时抽屉。
- 移动端 MUST 使用底部抽屉或全屏详情。
- 关闭引用抽屉后 MUST 恢复纯净的单栏对话布局。

引用详情最多显示：

- 来源类型。
- 知识库和文档名称。
- 命中片段。
- 文档位置。
- 相关度或检索说明。

没有引用时，页面 MUST NOT 显示空的“知识依据”区域。

## 8. 管理交互

工作台顶部 MUST 提供一个明确的“管理”按钮。管理按钮打开统一管理弹窗，默认不离开当前会话。

### 8.1 统一管理弹窗

- 桌面端建议宽度为 `880px`，最大高度不超过视口的 `84%`。
- 移动端 MUST 使用全屏弹窗。
- MUST 提供：数字员工、Skills、MCP、知识库、模型、节点。
- 标签数量较多时 MUST 使用左侧分区导航，不得压缩成无法阅读的单行标签。
- 保存、取消和危险操作 MUST 有清晰层级。

### 8.2 数字员工配置

数字员工配置 SHOULD 分为：

1. 基本信息。
2. 能力配置。
3. 行为指令。
4. 权限。

配置变更 MUST 明确区分“仅本次会话”和“保存为员工默认值”。

### 8.3 危险操作

删除员工、知识库、MCP 连接、模型和会话：

- MUST 二次确认。
- MUST 明确显示影响对象。
- MUST 使用文字按钮，不得仅使用垃圾桶图标完成最终确认。

## 9. 按钮可见性规则

### 9.1 始终可见

- 新建任务。
- 数字员工选择。
- 管理。
- 输入。
- 临时能力选择。
- 发送或停止。

### 9.2 条件出现

- 复制、重试、反馈和消息更多。
- 执行步骤展开。
- 引用入口。
- 运行错误恢复。

### 9.3 菜单或弹窗内

- 主题与语言。
- 模型高级参数。
- 完整执行日志。
- 导出与删除。
- Skill、MCP、知识库、节点详细配置。

熟悉图标的按钮 SHOULD 使用 Lucide 图标并提供工具提示。明确命令可使用“图标 + 文本”。不熟悉或具有风险的操作 MUST 使用文字。

## 10. 视觉令牌

### 10.1 浅色主题

浅色主题是默认主题。

| 令牌 | 值 |
| --- | --- |
| 页面背景 | `#F7F7F5` |
| 主内容背景 | `#FFFFFF` |
| 次级背景 | `#F1F1EE` |
| 悬停背景 | `#ECECE8` |
| 主文字 | `#171717` |
| 次级文字 | `#686863` |
| 弱文字 | `#92928C` |
| 边框 | `#E3E3DE` |
| 强边框 | `#CECEC7` |
| 选中与链接 | `#2563EB` |
| 成功 | `#16803D` |
| 警告 | `#B76500` |
| 错误 | `#C3322B` |

### 10.2 深色主题

| 令牌 | 值 |
| --- | --- |
| 页面背景 | `#101111` |
| 主内容背景 | `#181919` |
| 次级背景 | `#202121` |
| 悬停背景 | `#282929` |
| 主文字 | `#F3F3EF` |
| 次级文字 | `#ADADA6` |
| 弱文字 | `#7D7E78` |
| 边框 | `#2D2E2E` |
| 强边框 | `#414242` |

实现 MUST 通过语义 CSS 变量使用颜色，MUST NOT 在组件中随意新增颜色。

### 10.3 字体

- 中文正文：`Noto Sans SC`。
- 英文正文：`IBM Plex Sans`。
- 代码与日志：`JetBrains Mono`。
- 字体不可用时 MUST 提供合理的本地回退。
- 页面标题 SHOULD 为 `20px` 至 `24px`。
- 正文 SHOULD 为 `15px` 至 `16px`。
- 紧凑标签和状态 MUST NOT 小于 `12px`。
- 字间距 MUST 为 `0`，不得使用负字间距。

### 10.4 间距、圆角和阴影

- 间距基础单位 MUST 为 `4px`。
- 常用间距 MUST 从 `4 / 8 / 12 / 16 / 24 / 32px` 中选择。
- 控件圆角 MUST 为 `5px`。
- 弹窗和抽屉圆角 MUST NOT 超过 `8px`。
- 阴影只允许用于菜单、弹窗、浮层和抽屉。
- 页面分区和消息 MUST NOT 依赖厚重阴影。

## 11. 动效

- 悬停和按压：`120ms` 至 `150ms`。
- 折叠和内容显隐：`160ms` 至 `180ms`。
- 弹窗和抽屉：`180ms` 至 `220ms`。
- 推荐缓动：`cubic-bezier(0.2, 0.8, 0.2, 1)`。
- 页面 MUST NOT 使用大幅位移、弹跳或背景动画。
- 动态内容 MUST NOT 导致输入区、消息宽度或导航跳动。
- MUST 支持 `prefers-reduced-motion`。

## 12. 语言和主题

- 默认语言 MUST 为简体中文。
- MUST 支持中文和英文即时切换。
- 语言选择 MUST 持久化。
- 用户消息和模型回答 MUST NOT 因界面语言切换而自动翻译。
- 默认主题 MUST 为浅色。
- 主题选择 MUST 持久化。
- 首次打开 MUST NOT 自动跟随系统深色主题。
- 语言和主题入口 SHOULD 位于更多菜单及设置弹窗中。

## 13. 响应式规则

### 桌面端，宽度大于等于 `1200px`

- 使用收缩导航栏和居中消息区。
- 引用使用右侧临时抽屉。
- 管理使用居中弹窗。

### 平板端，宽度 `768px` 至 `1199px`

- 导航栏默认隐藏。
- 消息区保留合理边距。
- 引用和管理可使用覆盖式抽屉。

### 移动端，宽度小于 `768px`

- 顶部仅保留菜单、标题、数字员工和更多。
- 输入区触控目标 MUST 不小于 `44px`。
- 管理使用全屏弹窗。
- 引用使用底部抽屉。
- 所有文本 MUST 完整显示，不得与按钮重叠。

## 14. 可访问性

- 所有交互控件 MUST 可键盘操作。
- 焦点状态 MUST 清晰可见。
- 图标按钮 MUST 提供可访问名称和工具提示。
- 弹窗 MUST 锁定焦点并支持 `Escape` 关闭，危险确认除外。
- 颜色 MUST NOT 是状态的唯一表达方式。
- 文本与背景对比度 MUST 满足 WCAG AA。
- 流式输出更新 SHOULD 使用适度的 `aria-live`，不得逐 Token 打断屏幕阅读器。

## 15. 技术实现约束

- MUST 使用 React、TypeScript 和 Vite。
- 服务端数据 MUST 通过 TanStack Query 管理。
- 界面状态 SHOULD 使用局部状态；跨页面轻量状态可使用 Zustand。
- 中英文 MUST 使用 `react-i18next`，不得在组件中散落条件文案。
- 表单 MUST 使用 React Hook Form 和 Zod。
- 图标 MUST 使用 Lucide React，不得手绘重复图标。
- 主题 MUST 使用语义 CSS 变量。
- SSE MUST 使用可恢复的流解析，断开时给出明确状态。
- API 地址 MUST 通过环境变量配置。
- 开发环境 MUST 通过代理访问后端，避免页面代码绑定固定端口。

组件 MUST 覆盖适用的默认、悬停、聚焦、禁用、加载、空数据和错误状态。

## 16. 禁止模式

以下模式一律禁止：

- 紫色、粉色、蓝色的大面积渐变。
- 装饰性光球、光晕、网格和噪点背景。
- 首页 Hero、欢迎卡片或产品宣传区。
- 页面区域套卡片，卡片内部继续套卡片。
- 为每个执行步骤创建大卡片。
- 常驻执行详情栏或知识依据栏。
- 使用 Emoji 替代图标。
- 无意义的状态统计和虚构数据。
- 超大圆角、胶囊化所有按钮。
- 视口变化导致字体连续缩放。
- 依赖颜色区分成功、失败或选中状态。
- 把低频管理能力长期展示在工作台。

## 17. 页面验收清单

每个页面或重大组件提交前，必须逐项检查：

- [ ] 默认视图是否仍然以对话和回答为主。
- [ ] 执行步骤是否位于对应助手消息中。
- [ ] 执行完成后是否自动折叠。
- [ ] 知识依据是否默认隐藏。
- [ ] 引用是否可点击并显示准确来源。
- [ ] 是否存在可以移入菜单或弹窗的低频按钮。
- [ ] 是否只使用本规范定义的颜色、间距和圆角。
- [ ] 中英文切换是否完整。
- [ ] 默认是否为浅色主题。
- [ ] 浅色和深色是否都通过对比度检查。
- [ ] 桌面、平板和移动端是否无重叠、溢出和布局跳动。
- [ ] 键盘、触摸和屏幕阅读器是否可完成核心流程。
- [ ] 加载、空数据、错误和离线状态是否完整。
- [ ] 浏览器控制台是否无错误和警告。
- [ ] 是否完成真实后端接口和 SSE 流程验证。

任意 MUST 项或验收项不满足时，该页面不得标记为完成。

## 18. 变更流程

需要偏离本规范时，必须：

1. 说明当前规则。
2. 说明偏离原因和用户收益。
3. 评估对其他页面和组件的影响。
4. 先更新本文版本和变更记录。
5. 再修改设计或代码。
