# ADR-0002：首版采用 Spring Modulith 模块化单体

- 状态：Accepted
- 日期：2026-07-30

## 背景

项目功能较多，但主要由一个人开发，首要目标是简单启动和清晰展示。微服务会引入额外运行组件和分布式复杂度。

## 决策

首版只构建一个 Spring Boot 部署单元。按业务能力划分 Java 包模块，并使用 Spring Modulith 校验模块边界。

## 规则

- 模块 base package 是默认公开 API；
- 所有子包默认内部，项目统一使用 `internal` 命名表达实现边界；
- 额外公开的扩展接口使用 `@NamedInterface`；
- 每个模块在 `package-info.java` 中使用 `allowedDependencies` 声明依赖白名单；
- 模块依赖必须形成有向无环图；
- 不允许跨模块引用未公开的子包；
- 跨模块修改优先通过公开服务，异步解耦场景可使用应用事件；
- 不建立无边界的 `common/utils` 大杂烩模块。

## 后果

正面：

- 一个进程即可运行；
- 调试、事务和测试简单；
- 仍能展示明确的领域边界；
- 未来可按模块边界拆服务。

负面：

- 不能独立扩缩容某个模块；
- 长任务在单进程内执行；
- 必须持续运行架构校验，防止边界退化。
